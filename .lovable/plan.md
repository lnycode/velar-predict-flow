## Phase 1 — Trust & Real Predictions (Step 1)

Replace the random forecast with a real, evidence-backed model.

- **Edge function `predict-migraine-risk`**: pulls user's `migraine_entries` (last 90d) + live forecast from existing `get-weather` function. Computes per-day risk using:
  - Barometric pressure delta vs. 24h baseline (weighted heaviest — strongest evidence)
  - Humidity > user-specific threshold (derived from past attacks)
  - Temperature swings >8°C/24h
  - User-flagged triggers matching forecast conditions
  - Personal base rate (attacks/30d)
  - Logistic blend → 0–10 risk + confidence band based on sample size
- Replace `Math.random()` in `RiskForecast.tsx`; remove "Simulated Data" banner once real model is wired.
- **Evidence layer**: new `EvidenceTooltip` component on each risk factor citing source (Cephalalgia 2019, Headache 2015, etc.) — content table in `src/domain/constants/evidence.ts`.
- **Privacy & Compliance page** at `/privacy`: GDPR statement, data residency, "never sold" pledge, deletion request CTA. Linked from sidebar footer + auth page.

## Phase 2 — Onboarding & Mobile Foundation (Steps 2 + 3)

**Onboarding refactor** (`OnboardingFlow.tsx`):
- 4 short steps with progress bar, skippable optional fields, ~60s target.
- Show a **sample forecast preview** on the final step before submit (uses generic averages so cold-start has value).
- **Import wizard**: CSV import (Migraine Buddy export format + generic CSV) — new page `/import`, parsing in `src/domain/services/importService.ts`, bulk insert into `migraine_entries`.

**Native mobile polish** (Capacitor):
- Install `@capacitor/haptics`, `@capacitor/push-notifications`, `@capacitor/local-notifications`.
- Hook haptic feedback into log-attack, severity-slider, and toast success paths.
- Wire `usePushNotifications` to real barometric-drop alerts via the new edge function (scheduled via pg_cron every 3h).

- Document widget / Watch complication setup in `README.md` (native widget code lives outside web codebase — out of scope to build here, but hooks are ready).

## Phase 3 — Insight Quality & Care Team (Steps 4 + 5)

**Insights upgrade** (`InsightsPage.tsx`):
- **Weekly digest card**: plain-language summary generated by `lovable-ai` gateway (`google/gemini-2.5-flash`) from the user's last 7–30 days. Cached 24h in a new `weekly_insights` table.
- **Trigger correlation engine** in `src/domain/services/correlationService.ts`: Pearson/point-biserial correlations between logged triggers/weather and attack occurrence, with 95% CI. Replaces existing static trigger list.
- **Medication effectiveness**: time-to-relief stats from `effectiveness` + `duration` columns; rebound detection (attack within 24h after meds).
- **Cycle tracking**: new optional `cycle_day` field on `migraine_entries` + new `cycle_settings` columns on `profiles` (period start, avg length). Correlate phase vs. attacks.

**Care-team integration**:
- New table `shared_reports` (token, user_id, expires_at, scope).
- Edge function `create-share-link` → returns signed URL.
- Public route `/share/:token` → read-only report view (no auth required, RLS bypassed by token validation in edge function).
- **Pre-visit summary** generator: 1-page condensed PDF via existing `pdfExport.ts`, added as a button on `HistoryPage`.
